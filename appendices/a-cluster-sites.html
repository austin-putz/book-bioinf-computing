Appendix A — Cluster sites: SCINet and Nova

Optional. Reference for readers who use SCINet’s Ceres or Atlas, or Iowa State’s Nova. The chapters stay site-neutral and point here for the site-specific steps (Chapter 1, Chapter 2, Chapter 3, Chapter 4, Chapter 7, Chapter 9, Chapter 10).

How to read it:

  • The sites’ own pages are the authority. Sites change their systems; each section says when it was checked, and links the pages.
  • “Observed” marks something seen by logging in (November 2026), not read on a site page.
  • “Not stated” means the site’s pages do not say.
  • <user>, <netid>, <project>, and <group> stand for your own names.

Table A.10 is the one-table summary. If you use another cluster, the checklist in Section A.12 lists what to look up in its documentation.

A.1 Which site, and who can use it

Ceres and Atlas share accounts but not storage: the same project has a separate folder, with a separate quota, on each, and files made on one are not on the other (observed). Install the book environment on the cluster you will use.

A.2 Accounts

Checked 2026-11-21 against SCINet’s signup page and ISU’s Nova page and FAQ.

SCINet (Ceres and Atlas):

  1. ARS employees fill in the online form on the signup page (sign in with eAuthentication; be signed in to USDA Office 365 first). Contractors name their contracting officer’s representative as supervisor.
  2. A non-ARS collaborator needs an ARS employee sponsor, who submits the form on their behalf, with the collaborator’s details and the agreement that links them to ARS.
  3. The supervisor (the sponsor’s supervisor, for non-ARS users) approves. “It may take up to five business days to create an account after the request is approved.”
  4. You sign in through eAuthentication: with a LincPass, or, for non-USDA users, with Login.gov using the same e-mail address as the SCINet account (alternative logins).
  5. A new account has no project: your Slurm account is sandbox, for jobs of up to 2 hours (Atlas lists sandbox jobs as 2 hours; on Ceres, observed). A project is requested by its principal investigator, who must be a full-time ARS employee; its managers add members (project management). Membership can take a while to reach every system.
  6. On Atlas, your home folder may appear only a day after the welcome e-mail (accessing SCINet).

Nova:

  1. Your user name is your ISU NetID.
  2. Community access: anyone affiliated with Iowa State can ask for lower-priority access with no hardware purchase, through the HPC Cluster Access Request form linked from the Nova page. A community group gets 1 TB of group working space.
  3. Sponsored access: groups that bought nodes get higher priority and larger limits; the group’s owner adds members.
  4. Instructional access: an instructor requests it for a class, with the same request form.
  5. How long approval takes: not stated. Access for collaborators outside Iowa State: not stated.

A.3 Logging in

Section 2.4 teaches ssh; this is each site’s version. Checked 2026-11-21 against SCINet’s SSH page, MSU’s connect page, and ISU’s Nova SSH page.

SCINet’s own advice is that “for most use cases, you do not need” SSH: its Open OnDemand portal in a browser is simpler (Section A.7).

Observed on all three (November 2026): an SSH login is a login shell, the site’s ~/.bash_profile reads ~/.bashrc, and a command sent with ssh host 'command' reads ~/.bashrc too (Section 7.6). SCINet’s banner is printed by SSH on its error output, so it does not disturb scp or rsync.

A.5 Storage, quotas, and backups

The full version of Table 3.3. Checked 2026-11-21 against SCINet’s storage guide and project-management page, MSU’s storage page, and ISU’s file storage page.

Two Nova notes (observed 2026-11-20): group_storage_usage lists every member’s use and file count (OBJUSED); and ISU’s helper commands my_workdir and cdw did not work then, so use your folder’s path. Deleting files on Nova’s /work frees space only after about five days, when the snapshots that hold them expire.

Permissions on shared folders (Section 7.2; observed 2026-11-20 and 21):

Where to put the book environment (Section 2.2): in your project or group folder, never in home, with pixi’s cache on the same storage. For example, /project/<project>/<user>/bioinf-computing on Ceres or Atlas and /work/<group>/<netid>/bioinf-computing on Nova, with PIXI_CACHE_DIR set to a folder beside it. One book environment is about 1.3 GB and 15,500 files (less on Nova’s compressed /work).

A.6 Interactive sessions

Checked 2026-11-21 against the pages linked below and by starting a session on each cluster. Chapter 1’s first session uses srun --cpus-per-task=1 --mem=4G --time=01:00:00 --pty bash -l; each site adds its own options. Full SLURM teaching is Chapter 10.

  • Ceres: salloc -A <project> gives one core, about 6 GB, and a shell for 2 hours (SLURM guide). Partition ceres (default 2 hours, at most 3 weeks); scavenger runs longer but can be stopped. sinfo -s (observed) lists only these two, with partition limits of 60 and 21 days; the 3-week limit on ceres comes from its QOS, not the partition.

    Observed: srun -A <project> --cpus-per-task=1 --mem=4G --time=00:30:00 --pty bash -l works and gives a shell on a compute node. sacctmgr -n show assoc user=$USER format=account%30 lists the accounts you may use. On arrival the node prints its settings: TMPDIR and Apptainer’s cache are set to the node’s /tmp, and TMOUT=5400 logs an idle shell out after 90 minutes.

  • Atlas: -A <project> is required. salloc -A <project> only reserves the node; srun --pty --preserve-env bash then puts you on it, or use srun -A <project> --pty --preserve-env bash in one step (Ceres and Atlas differences). Default partition atlas; others for large memory and GPUs, listed in MSU’s Atlas specifications. sinfo -s (observed) shows atlas, bigmem, four GPU partitions, development, and service, all with no time limit, so the limits come from the QOS.

    Observed: the same srun -A <project> ... --pty bash -l line as on Ceres works in one step, and nothing is printed on arrival.

  • Nova: ISU’s examples have no account option, e.g. salloc -N 1 -n 8 -t 4:00:00 (SLURM page); default partition nova. ISU’s pages say jobs run up to two weeks; the OnDemand form showed a 31-day limit for nova (observed).

    Observed: srun --cpus-per-task=1 --mem=4G --time=00:30:00 --pty bash -l works with no -A; SLURM charges your default account (list yours with the sacctmgr line above). On arrival the node prints its settings, as Ceres does: TMPDIR and Apptainer’s cache on the node’s /tmp, TMOUT=5400 (90 idle minutes), and Apptainer set to make /work, /ptmp, and the other shared file systems visible inside containers. sinfo -s (observed) shows nova (31 days), interactive (8 hours; the one ISU’s VS Code page says to pick), instruction (2 days), scavenger, reserved, nova-arm, and a one-minute allnodes.

  • End the session with exit. After srun ... --pty, exit ends the job too (squeue -u $USER showed nothing left on all three, observed); a reservation from salloc may need scancel <jobid> as well.

  • Internet from compute nodes: not stated by any of the three. Observed on Ceres: yes (curl -sI https://pixi.sh answered). On Atlas: yes, through a web proxy (the reply begins HTTP/1.1 200 Connection established, which is the proxy speaking). Tools that read the standard https_proxy setting, as curl does, work without changes. The node sets https_proxy, http_proxy, and no_proxy for you (observed). On Nova: yes, directly (observed). So on all three, downloads work inside an interactive session. On Atlas both the pixi installer and pixi install --locked worked through the proxy with no changes (observed 2026-11-22). The book environment took 29 seconds to install on Atlas, 54 on Ceres, and 10 on Nova; it used about 1.3 GB on SCINet and 0.8 GB on Nova’s compressed /work, with the cache’s files shared rather than copied on all three.

A.7 VS Code

Section 2.3 explains the routes. Checked 2026-11-21 against SCINet’s VS Code guide, MSU’s connect page, and ISU’s VS Code page.

The OnDemand start form asks the same things under different names (observed on all three):

Set the starting folder to your project or group folder. End a session with Cancel on its card under My Interactive Sessions: closing the browser tab does not end it, and it keeps its node until cancelled or out of time (observed on both).

Extensions fill home. Both SCINet and ISU say to move the extensions folder to project storage and leave a link in its place, once:

Terminal (cluster)
1mkdir -p /project/<project>/<user>/.local/share
mv ~/.local/share/code-server /project/<project>/<user>/.local/share/
ln -s /project/<project>/<user>/.local/share/code-server ~/.local/share/code-server
1
On Nova, use /work/<group>/<netid> instead of /project/<project>/<user>. Do this with no VS Code session running.

A.8 Software on the site

Checked 2026-11-21 against SCINet’s modules and Apptainer guides and ISU’s modules page.

  • Modules on all three: module avail (or module spider), module load <name>, module list. On Atlas some modules appear only after a gcc module is loaded.
  • Containers: Apptainer on SCINet (on Atlas, module load apptainer first; run it on a compute node). Nova: not documented on the pages read, but module avail apptainer lists versions 1.1.5 to 1.4.0 (observed), from three dated software trees.
  • Asking for software: SCINet’s software request form; new system-wide software needs a security review that “takes a few weeks”. Nova: ISU Research IT (Section A.10).
  • The book’s way: the book environment with pixi in your project storage, for everything it covers; site modules only for what it does not.

A.9 Shared reference data

  • Ceres has a shared /reference area, including ready-made containers in /reference/containers. Its main folders (observed): data, containers, llms, workshops, and workbook, plus site-admin folders.
  • Atlas has /reference, copied from Ceres’s /reference/data every night. Observed: data, containers, llms, models, workshops, workbook, and a README that says the folder is “for reference datasets”, “read only on atlas”, and “sync’d nightly from” Ceres’s /reference/data.
  • Nova: not stated, and none seen: the top-level /shared folder holds the site’s own configuration (SLURM, OnDemand, module files), not reference data (observed).

What /reference/data holds (observed; the same on Ceres and Atlas): mostly the large databases that annotation and classification tools need, one folder per tool, e.g. alphafold, BUSCO, eggnogdb, gtdbtk, kaiju, humann, and Dfam, plus a Genome folder. Before downloading a tool’s database, look here first; some of these databases are very large.

If your site has none, keep references once in a lab-shared folder (Section 3.5).

A.10 Getting help

Whatever the site, say which cluster, node, and job ID; give the exact command, the folder you ran it in, and the complete message; and say what you already checked (Chapter 4). Writing to ISU from a non-ISU address, include your NetID.
